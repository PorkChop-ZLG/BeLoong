# Minecraft 1.21.1 NeoForge 试炼刷怪笼配置文档

> **核对版本**：Minecraft 1.21.1、NeoForge 21.1.219。  
> **核对依据**：本机 NeoForm 反编译源码中的 `TrialSpawner`、`TrialSpawnerConfig`、`TrialSpawnerData`、`TrialSpawnerBlockEntity`、`TrialSpawnerState` 和 `SpawnData`。  
> 本文所有“可执行命令”代码块均为 SNBT，不包含注释；带说明的结构示意不能直接粘贴到游戏。

## 一、直接可用的命令

### 1.1 最小普通试炼刷怪笼

```mcfunction
/give @p minecraft:trial_spawner[minecraft:block_entity_data={id:"minecraft:trial_spawner",normal_config:{spawn_potentials:[{data:{entity:{id:"minecraft:zombie"}},weight:1}]}}]
```

`minecraft:` 命名空间可省略，但完整写法更明确。试炼刷怪笼的方块实体数据只能由有权限使用管理员方块数据的玩家放置，因为其方块实体返回 `onlyOpCanSetNbt() = true`。

### 1.2 单只自定义冰龙

下面的实体标签含有 `id` 以外的字段，因此不会调用 Ice and Fire 龙的 `finalizeSpawn`；年龄、性别和变种不会被随机重置。

```mcfunction
/give @p minecraft:trial_spawner[minecraft:block_entity_data={id:"minecraft:trial_spawner",normal_config:{spawn_range:1,total_mobs:1.0f,simultaneous_mobs:1.0f,total_mobs_added_per_player:0.0f,simultaneous_mobs_added_per_player:0.0f,ticks_between_spawn:20,spawn_potentials:[{data:{entity:{id:"iceandfire:ice_dragon",AgeTicks:1800000,Gender:0b,Variant:"sapphire",Hunger:50,AgingDisabled:1b,AttackDecision:1b,Health:20.0f,active_effects:[{id:"minecraft:instant_health",amplifier:10,duration:1,show_particles:0b}]}},weight:1}],loot_tables_to_eject:[]}}]
```

这只龙为 75 天、Stage 4、雌性、蓝宝石变种。`AgingDisabled:1b` 固定年龄。短暂的瞬间治疗用于在 Ice and Fire 按年龄刷新最大生命值后补满生命；直接写入 `attributes[].base` 不能稳定覆盖龙的动态属性，原因见龙 NBT 文档。

### 1.3 普通/不祥两种龙

`ominous_config` 在读取时会以 `normal_config` 为基础，再用显式给出的不祥字段覆盖。下面仅覆盖实体池和奖励，其他数字参数继承普通配置。

```mcfunction
/give @p minecraft:trial_spawner[minecraft:block_entity_data={id:"minecraft:trial_spawner",normal_config:{spawn_range:1,total_mobs:1.0f,simultaneous_mobs:1.0f,total_mobs_added_per_player:0.0f,simultaneous_mobs_added_per_player:0.0f,ticks_between_spawn:20,spawn_potentials:[{data:{entity:{id:"iceandfire:ice_dragon",AgeTicks:1800000,Gender:1b,Variant:"blue",Hunger:50,AgingDisabled:1b,AttackDecision:1b,Health:20.0f,active_effects:[{id:"minecraft:instant_health",amplifier:10,duration:1,show_particles:0b}]}},weight:1}],loot_tables_to_eject:[]},ominous_config:{spawn_potentials:[{data:{entity:{id:"iceandfire:ice_dragon",AgeTicks:2400000,Gender:1b,Variant:"silver",Hunger:50,AgingDisabled:1b,AttackDecision:1b,Health:20.0f,active_effects:[{id:"minecraft:instant_health",amplifier:10,duration:1,show_particles:0b}]}},weight:1}],loot_tables_to_eject:[{data:"minecraft:spawners/ominous/trial_chamber/key",weight:1}]}}]
```

## 二、顶层方块实体数据

`block_entity_data` 中可被 1.21.1 试炼刷怪笼 Codec 读取的字段如下：

| 字段 | 类型 | 默认值 | 约束与用途 |
|---|---:|---:|---|
| `id` | String | 无 | 物品数据组件要求的方块实体类型，必须为 `minecraft:trial_spawner` |
| `normal_config` | Compound | 默认配置 | 普通模式配置；不是必填字段，但没有实体池时刷怪笼保持 inactive |
| `ominous_config` | Compound | 见下文 | 不祥配置的覆盖项 |
| `target_cooldown_length` | Int | `36000` | `0..2147483647`，奖励流程开始时写入冷却结束时间 |
| `required_player_range` | Int | `14` | `1..128`，玩家检测半径 |
| `registered_players` | UUID 列表 | `[]` | 运行时数据，不建议在 `/give` 中写入 |
| `current_mobs` | UUID 列表 | `[]` | 当前归属于刷怪笼的怪物 UUID，运行时数据 |
| `cooldown_ends_at` | Long | `0L` | 绝对游戏时间，运行时数据 |
| `next_mob_spawns_at` | Long | `0L` | 下次生成的绝对游戏时间，运行时数据 |
| `total_mobs_spawned` | Int | `0` | 已生成数量，非负，运行时数据 |
| `spawn_data` | Compound | 无 | 缓存的“下一只实体”，类型为 `SpawnData`，不是带 `weight` 的条目 |
| `ejecting_loot_table` | String | 无 | 当前奖励表，运行时数据 |

### 2.1 文档中不应出现的 `state`

`state` 不是方块实体 NBT。试炼刷怪笼状态是方块状态属性 `trial_spawner_state`，值为：

`inactive`、`waiting_for_players`、`active`、`waiting_for_reward_ejection`、`ejecting_reward`、`cooldown`。

不祥外观也是方块状态属性 `ominous`。通常不要在物品上强行写这两个状态，状态机会根据配置和玩家自动转换。

### 2.2 `ominous_config` 的继承规则

1. `TrialSpawnerBlockEntity.loadAdditional` 先复制整个 `normal_config`。
2. 再把 `ominous_config` 中存在的键合并到副本中。
3. 所以省略某个不祥字段时，它继承普通值，而不是使用该字段的全局默认值。
4. 完全省略 `normal_config` 时，普通和不祥均使用 `TrialSpawnerConfig.DEFAULT`。

## 三、config 字段

| 字段 | 类型 | 默认值 | Codec 范围 | 说明 |
|---|---:|---:|---:|---|
| `spawn_range` | Int | `4` | `1..128` | X/Z 随机偏移范围；Y 在刷怪笼上下 1 格内随机 |
| `total_mobs` | Float | `6.0f` | `0..Float.MAX_VALUE` | 第一名玩家对应的基础总数 |
| `simultaneous_mobs` | Float | `2.0f` | 同上 | 第一名玩家对应的同时存活上限 |
| `total_mobs_added_per_player` | Float | `2.0f` | 同上 | 每名额外玩家增加的总数 |
| `simultaneous_mobs_added_per_player` | Float | `1.0f` | 同上 | 每名额外玩家增加的同时上限 |
| `ticks_between_spawn` | Int | `40` | `0..2147483647` | 成功生成后的间隔；失败尝试不会增加已生成数量 |
| `spawn_potentials` | 加权列表 | `[]` | 可为空 | 生成实体池 |
| `loot_tables_to_eject` | 加权列表 | 原版消耗品与钥匙，各权重 1 | 可为空 | 完成后每名注册玩家各弹出一次所选奖励表 |
| `items_to_drop_when_ominous` | String | `minecraft:spawners/trial_chamber/items_to_drop_when_ominous` | 战利品表 ID | 不祥战斗期间，由头顶的不祥物品生成器使用；不是通关奖励 |

### 3.1 多玩家公式

源码传入的是“额外玩家数”：

```text
extraPlayers = max(0, registeredPlayers - 1)
目标总数 = floor(total_mobs + total_mobs_added_per_player * extraPlayers)
同时上限 = floor(simultaneous_mobs + simultaneous_mobs_added_per_player * extraPlayers)
```

文档或配置若把传入值再减 1，会少计算一名玩家。

### 3.2 奖励节奏

击杀最后一只已登记怪物后：

1. 等待 40 tick 后打开挡板。
2. 每 30 tick 处理一名 `registered_players` 中的玩家。
3. 每名玩家从同一个已选中的 `loot_tables_to_eject` 战利品表生成一次奖励。
4. 所有登记玩家处理完后进入冷却。

因此“每 1.5 秒向每名玩家弹出一次”应理解为每隔 30 tick 处理下一名玩家，而不是每名玩家反复获得奖励。

## 四、`spawn_potentials` 与 `spawn_data`

### 4.1 加权条目

```snbt
spawn_potentials:[
  {data:{entity:{id:"namespace:entity"}},weight:3},
  {data:{entity:{id:"namespace:rare_entity"}},weight:1}
]
```

每项的 `weight` 必须是正整数。`data` 是 `SpawnData`，包含：

| 字段 | 是否必需 | 说明 |
|---|---|---|
| `entity` | 是 | 完整实体 NBT；至少包含合法的字符串 `id` |
| `custom_spawn_rules` | 否 | 自定义方块光和天空光范围 |
| `equipment` | 否 | 1.21.1 新的装备表引用与掉落概率；不要与实体 NBT 的 `HandItems`/`ArmorItems` 混淆 |

### 4.2 `custom_spawn_rules` 在 1.21.1 中有效

当前 1.21.1 源码明确调用 `SpawnData.CustomSpawnRules.isValidPosition`。旧文档引用 MC-266707 并断言该字段被忽略，不适用于本次核对的 1.21.1 实现。

```snbt
custom_spawn_rules:{block_light_limit:{min_inclusive:0,max_inclusive:7},sky_light_limit:{min_inclusive:0,max_inclusive:15}}
```

两种亮度范围均限制在 `0..15`。空对象 `{}` 合法，两个范围都使用 `0..15`，等价于不额外限制光照。它不会绕过以下检查：

- 实体注册的 `SpawnPlacements` 规则；
- 生成包围盒无碰撞；
- 刷怪笼到生成点有视线；
- `Mob.checkSpawnObstruction`；
- 非和平难度且 `doMobSpawning=true`。

### 4.3 `spawn_data` 不是加权条目

正确：

```snbt
spawn_data:{entity:{id:"minecraft:zombie"}}
```

错误：

```snbt
spawn_data:{data:{entity:{id:"minecraft:zombie"}},weight:1}
```

`spawn_data` 是已选中的下一只实体缓存。通常只配置 `spawn_potentials`，让游戏自行选择并维护 `spawn_data`。手工同时设置二者时，第一次生成优先使用 `spawn_data`。

### 4.4 实体 NBT 与 `finalizeSpawn`

试炼刷怪笼在实体 NBT **恰好只有**字符串 `id` 一个键时调用 `Mob.finalizeSpawn`。只要再添加 `AgeTicks`、`Health`、`Variant` 等任意键，就跳过 `finalizeSpawn`。NeoForge 仍会发布 `FinalizeSpawnEvent`，但默认不会调用实体的初始化方法。

这对 Ice and Fire 龙尤其重要：

- 只有 `id`：龙会随机生成 1..80 天年龄、随机性别、随机合法变种、`Hunger=50`。
- 含自定义 NBT：上述随机初始化不运行；没有写出的 IAF 字段大多通过 `getInt/getString/getBoolean` 读成 `0`、空字符串或 `false`。

## 五、实体通用 NBT 格式

### 5.1 属性

1.21.1 使用小写 `attributes`、`id`、`base`、`modifiers`：

```snbt
attributes:[{id:"minecraft:generic.max_health",base:20.0d,modifiers:[{id:"belong:trial_bonus_health",amount:980.0d,operation:"add_value"}]}]
```

普通生物可直接通过 `base` 改属性。Ice and Fire 龙会在读取 NBT 后按 `AgeTicks` 重写最大生命、攻击、移动速度和护甲的 `base`，但不会删除自定义永久 modifier。因此龙需要永久强化时应使用唯一命名空间 ID 的 `modifiers`，并相应设置 `Health`；不要声称 `base:1000` 会稳定保留。

### 5.2 装备槽顺序

```snbt
HandItems:[{id:"minecraft:iron_sword",count:1},{}]
ArmorItems:[{id:"minecraft:leather_boots",count:1},{id:"minecraft:leather_leggings",count:1},{id:"minecraft:leather_chestplate",count:1},{id:"minecraft:iron_helmet",count:1}]
```

- `HandItems`：主手、副手。
- `ArmorItems`：脚、腿、胸、头。旧文档若写成头到脚顺序是错误的。
- 物品栈字段为小写 `id`、`count`、`components`。
- `HandDropChances` 和 `ArmorDropChances` 仍为 float 列表。

## 六、奖励列表

```snbt
loot_tables_to_eject:[{data:"minecraft:spawners/trial_chamber/key",weight:1}]
```

- 省略字段：使用默认的消耗品/钥匙加权列表。
- 写 `[]`：不生成通关奖励，这是最明确的禁用方式。
- `{data:"minecraft:empty",weight:1}`：选择空战利品表，效果也是无物品，但仍走奖励表流程。
- `items_to_drop_when_ominous` 与此列表用途不同，不能用它配置通关不祥钥匙。

## 七、排错清单

1. **刷怪笼保持 inactive**：`spawn_potentials` 为空，或实体 `id` 无效。
2. **始终不生成**：检查和平难度、`doMobSpawning`、碰撞空间、视线和实体自身生成规则。
3. **自定义龙为 0 饥饿或贴图异常**：自定义实体 NBT 抑制了 `finalizeSpawn`，但遗漏 `Hunger` 或写了非法 `Variant`。
4. **龙年龄/颜色被随机化**：实体标签只有 `id`；加入所需字段即可抑制 `finalizeSpawn`。
5. **不祥配置部分字段“神秘继承”**：这是 `normal_config` 复制后合并的设计，不是两个完全独立对象。
6. **命令解析失败**：可执行 SNBT 中不能使用 `//` 注释，也不要使用 Java 示例中的省略号。
7. **物品放置后没有 NBT**：试炼刷怪笼只允许管理员权限写入方块实体数据。
