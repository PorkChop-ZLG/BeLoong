# 星辰龙星光维度规则（starlight_dimensions.json）

> 本文说明 `kubejs/data/star_dragon/starlight_dimensions.json` 这份数据包文件的用途、格式与取值依据。
> 相关文档：`docs/龙之生存魔改总结.md` 第 4.4 节（龙宫惩罚免疫）、`docs/龙之生存附属模组适配准则.md` 第四章（龙宫维度诅咒豁免）。

---

## 一、这个文件解决什么问题

星辰龙的星光条（supply：`star_dragon:star_points`）由附属模组的 Java 代码逐 tick 直接写入，**不经过 Dragon Survival 的惩罚条件判定**。

因此 `kubejs/data/star_dragon/dragonsurvival/dragon_penalty/starlight_flux.json` 里的 `condition` 只能控制「星力枯竭伤害结不结算」，管不到星光条本身的涨落：

- 惩罚条件：`DragonPenalty#apply`（DS 2.0.71 `registry/dragon/penalty/DragonPenalty.java:86`）把条件结果交给 `SupplyTrigger#matches`；而 `starlight_flux` 的 `reduction_rate` 与 `regeneration_rate` 都是 `0.0`，DS 那条供给通道双向都是空转。条件为假时唯一的效果是「不结算伤害」。
- 星光条数值：`StarlightBarHandler#updateStarBar`（star_dragon 2.2.x）每 tick 用 `StarlightCalculator#calculate` 算出的「环境星力」直接写进 supply。

结论：要让星光条在不同维度表现不同，**必须改「环境星力」，而不是改惩罚条件**。这就是本文件存在的唯一原因。

本文件由 `StarlightDimensionRules` 读取，通过 `AddReloadListenerEvent` 注册，属于服务端数据包资源。

## 二、位置与生效方式

- 本包放在 `kubejs/data/star_dragon/starlight_dimensions.json`。
- 任何数据包放在 `data/star_dragon/starlight_dimensions.json` 均生效，**不需要复制模组 jar 内的原文件**。
- 生效时机：进世界或执行 `/reload`。重载会同时清空 `StarlightCalculator` 的公式缓存，不会残留旧值。
- 合并规则：多个数据包的同名文件**按键合并**，高优先级覆盖低优先级。本文件只写 `dimensions`，因此模组 jar 里的 `default` 与三个速率字段（`base_increase_rate` / `base_decrease_rate` / `acceleration_strength`）保持原值。

## 三、字段格式

```json
{
  "dimensions": {
    "<维度 ID>": "<命名公式>"
  }
}
```

值也可以写成对象形式：`"<维度 ID>": { "type": "fixed", "value": 0.7 }`。

公式由 `StarlightFormula` 解析：

| 写法 | 含义 |
|---|---|
| `"max"` | 环境星力恒为 100% |
| `"min"` | 环境星力恒为 0% |
| `{"type":"fixed","value":0.7}` | 环境星力恒为 70% |
| `{"type":"sky_darken","weather":true,"sky_open":true}` | 按天空亮度计算，可用 `weather` / `sky_open` 关掉天气与头顶遮挡系数 |
| 未列出该维度 | 走 `default`；`default` 为 `auto` 时按维度类型判断（有天花板 → `min`，无天空光 → `max`，否则走主世界的天空亮度公式） |

`"the_end"` 与 `"the_nether"` 已在模组 jar 内分别配为 `max` / `min`，本文件不重复声明。

## 四、环境星力与星光条的关系

`updateStarBar` 只有两个方向，**没有中间稳态**：

| 环境星力 | 星光条 |
|---|---|
| 大于 0.5 | 向 100% 上涨，越偏离 50% 越快 |
| 等于 0.5 | 完全不动 |
| 小于 0.5 | 向 0% 下跌 |

星尘块加成是额外叠加的（非主世界公式才叠加，每个 +0.1，上限 1.0），所以「固定值 + 星尘块」可以超过 1.0。

## 五、本包当前配置

| 维度 | 公式 | 环境星力 | 星光条表现 |
|---|---|---|---|
| `beloong:loong_palace`（龙宫） | `fixed 0.5` | 50% | 冻结在进入时的数值，不再下跌 |
| `twilightforest:twilight_forest`（暮色森林） | `fixed 0.7` | 70% | 缓慢回升，空条到满约 17 秒 |
| `eternal_starlight:starlight`（永恒星光） | `max` | 100% | 快速回满，空条到满约 7 秒 |
| 其它维度 | 未列出，走 `auto` | 按维度类型 | 白天掉、夜里涨 |

时间按 `base_increase_rate = 0.005`、`acceleration_strength = 1.0`、身边无星尘块推算。

取值理由：

- **龙宫**是整合包的「安全区」，取 0.5 让星光条完全静止——星辰龙在其中既不继续被扣，也不额外获利（同时避开 `max` 带来的副作用，见第六节）。
- **暮色森林**定位「微光环境」，取 0.7 即恢复速度为满速的 40%：不惩罚，但回得慢。
- **永恒星光**是星辰龙的故乡维度，取满值。

## 六、注意事项

1. **0.5 以外的值都会一路走到 0% 或 100%**。想要「停在某个中间值」当前公式做不到，除非改 Java。
2. **成就「星空！」（`star_dragon:star/night_sky`）的判定是环境星力 ≥ 1.0，与星光条实际数值无关**（`StarlightBarHandler` 在 `starPower >= 1.0` 时直接授予）。所以 `max` 的维度一进入就会发放该成就；不想发则写 `{"type":"fixed","value":0.95}` 之类（星光条仍会涨满，但环境星力不到 1.0）。
3. **星尘块会叠加**：在 `fixed 0.7` 的维度里，身边有 3 个及以上星尘块时环境星力会被顶到 1.0，同样会触发第 2 条的成就判定。
4. **本文件只影响星光条与相关判定使用的「环境星力」**，不改变惩罚条件，也不改变 `starlight_flux` 的伤害数值。
5. **维度 ID 写错不会报错**，只会静默不生效。新增维度前先确认 ID（读模组 jar 的 `data/<命名空间>/dimension/*.json`，或用 `/execute in` 的补全确认）。

## 七、校验方法

1. **语法**：`dimensions` 下每个值要么是字符串，要么是带 `type` 的对象；JSON 不支持注释。
2. **合并结果**：确认目标维度确实落在本文件的键上，没有被更高优先级的数据包覆盖。
3. **数值**：把公式代入第四节的两分支逻辑逐 tick 推算，比进游戏观察快得多。
4. **实机**：星辰龙形态分别进入三个维度观察星光条——龙宫应完全不动、暮色应缓慢回升、永恒星光应快速回满。
